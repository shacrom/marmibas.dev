Mi primera etapa profesional fue como desarrollador frontend en Cleverpy Machine Learning. Participé en el diseño y desarrollo de una página web construida con React, gestionando el estado de la aplicación con Redux, autenticando contra el backend mediante JWT y trabajando los estilos en Sass para mantenerlos organizados conforme el proyecto crecía. El trabajo iba más allá de implementar pantallas: incluía reuniones con el cliente para acordar funcionalidades, revisar prototipos y ajustar prioridades. Esa parte me obligó a aterrizar lo que se hablaba en cada reunión a tareas concretas de desarrollo y a preguntar lo que hiciera falta para no construir sobre supuestos.

Tras esos primeros meses me incorporé al equipo de backend de la misma empresa. El trabajo combinaba dos frentes: por un lado, traducir lógica existente en Python a Java para integrarla en los servicios principales; por otro, mantener y evolucionar código Java apoyado en Spring, con persistencia sobre PostgreSQL. Pasar de un lenguaje a otro me obligó a entender bien la intención del código original antes de tocar nada y a buscar el equivalente correcto en Java sin arrastrar costumbres propias de Python. Fue también mi primer contacto serio con GitFlow trabajando en equipo, lo que me dio orden a la hora de organizar ramas, abrir pull requests y mantener la integración limpia con el resto del proyecto.

Cleverpy fue el punto de partida sobre el que construí todo lo que vino después: trato directo con cliente, integración con servicios externos vía API REST y un primer contacto serio con stacks modernos —tanto en frontend como en backend— en producción.
